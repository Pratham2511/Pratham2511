# Profile activity

The activity graphics are generated by `scripts/update_profile_activity.py` using Python's standard library. Contribution totals and streaks come directly from GitHub's visible public profile calendar; public pull-request statistics come from the GitHub API. They do not depend on a third-party stats-card server.

The GitHub Actions schedule runs automatically every two hours at minute 23 of each even UTC hour (`23 */2 * * *`): 00:23, 02:23, through 22:23 UTC (05:53, 07:53, through 03:53 the next day in Asia/Kolkata). Manual dispatch and changes to the generator/workflow also trigger it. Scheduled jobs can run late; this is a two-hour target, not a real-time guarantee. The workflow runs on the default branch without requiring a manual start or a local computer to stay on. No external monitor or local background task is installed.

The workflow uses the job's built-in `GITHUB_TOKEN`, limited to writing this profile repository. No personal access token or extra secret is required for public statistics. It commits only five generated assets, using the GitHub Actions bot identity, and never modifies the README, project entries or other repositories. Protected-branch or token-policy failures must be reported, not bypassed. No workflow executes on pull-request events or untrusted forks.

## Metrics

- **Contributions · past year:** the heading total from `https://github.com/users/Pratham2511/contributions`, checked against every displayed day's count. This includes anonymous private contribution counts when the owner has made them publicly visible, as well as activity in owned projects. It is not a merged-PR count. The GraphQL calendar can differ from the website, so it is not used for this metric.
- **Longest daily streak · past year:** the longest consecutive run inside the displayed calendar window; not an all-time claim.
- **Current daily streak:** consecutive active dates ending on the calendar's last displayed date, or the day before if that date is still empty. It uses the same visible daily counts as the total, without independently rebucketing dates.
- **Authored merged PRs:** public, merged pull requests authored by Pratham2511, excluding repositories owned by Pratham2511. All-time within GitHub's searchable public history.
- The distinct external repository count remains metadata only; it is not a displayed counter. Assignment requests, peer reviews, comments, closed-unmerged PRs and own-project PRs do not inflate authored merged PRs.
- **Top external repositories:** individual repositories ranked by the same merged authored PR count; ties sort by full repository name. CODERCOPS projects are separate repositories, not silently pooled into one.
- **Open PRs:** a count only of open public PRs authored by Pratham2511 to external repositories. Individual titles/links are not displayed or retained in the generated summary.

The contribution coordinator's historical ledger is separate from this standard authored-PR statistic: it can include explicitly credited maintainer-authored landings or historical repositories that are no longer publicly accessible. The profile uses only the public authored PRs returned by GitHub, without copying or padding the historical ledger total. Generating a profile graphic does not resume retired project work.

The generator checks complete PR pagination and calendar/identity integrity. The public calendar is fetched in English without an Authorization header, login cookie or personal token. It accepts only a complete, consecutive past-year calendar whose heading equals the sum of all daily tooltips. Missing days, unknown tooltip formats, changed page markup or disagreeing totals fail the job instead of falling back to the API's smaller count. API errors, changing pagination counts or more than 1,000 matching PRs also fail. Existing published graphics remain until a successful update. No private repository names or contents are requested for the calendar.

There is no displayed contribution-calendar grid or peer-review statistic. Graphics have transparent backgrounds with dark/light text versions and narrow-layout variants. They contain no executable content or external asset requests. A README cannot force GitHub’s page theme or outer background. Only aggregate/public display data and the calendar source URL are stored in `assets/profile-activity.json`. GitHub may cache signed-in and signed-out views differently; the card is a timestamped snapshot of the public calendar at its last successful run, not an always-live copy of an individual browser session.

For an offline preview, pass a captured public API response with `--input-json PATH` and optionally `--updated-at ISO_TIMESTAMP`. Never commit API tokens or raw authenticated responses. A local render is not proof that a hosted run succeeded; confirm the current run in the repository Actions tab.
